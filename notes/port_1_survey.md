# 阶段一：代码现状勘察问卷

## 你的任务

阅读本仓库中**任务下发（dispatch）**和**依赖解算（painter）**相关的代码，回答下面的问题，
输出一份现状报告。

## 硬性要求

1. **不要修改任何代码。** 这个阶段只读不写。
2. **每个回答都要给出依据**：文件路径 + 行号 + 关键代码片段。
3. **不确定就写「不确定」，不要猜。** 猜错比不知道更糟——后续会有人根据这份报告决定怎么
   改代码，一个编造的答案会直接变成一个 bug。
4. **不要提出改进建议，不要设计方案。** 只描述现状。
5. 如果某个问题在本仓库里**不存在对应概念**，就写「不存在」，并说明最接近的是什么。

## 背景（只是为了让你知道为什么问这些，不要照着它去改代码）

有一个「提前下发」的功能要移植进来：当一个任务 P 被下发到计算单元时，如果某个后继任务 S
唯一还没完成的前驱就是 P，那就把 S 也提前放到计算单元上，让 S 在计算单元侧等 P 完成后立即
开始，省掉 S 走一遍「完成信号 → 依赖解算 → 就绪队列 → 下一轮下发」的流程。

下面的问题都是为了搞清楚：这套逻辑要落到本仓库里，得挂在哪些现有机制上。
